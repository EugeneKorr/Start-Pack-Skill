# Test-Driven Development

**ПРАВИЛО: сначала тест. Смотри, как он падает. Потом код.**

## Red-Green-Refactor цикл

### 🔴 RED
- Напиши тест, демонстрирующий желаемое поведение
- Запусти — он ДОЛЖЕН упасть
- Убедись, что падает по нужной причине (не из-за синтаксической ошибки)

### 🟢 GREEN
- Напиши минимальный код, чтобы тест прошёл
- Не оптимизируй — только пройди тест

### 🔵 REFACTOR
- Улучши код, сохраняя зелёный тест
- Убери дублирование, улучши читаемость

## Запрещено

- Писать производственный код до падающего теста
- Пропускать фазу «смотри, как падает»
- Писать тест после кода (это не TDD)

Если код написан до теста — удали код, начни с теста.

## Задача считается завершённой когда

Каждая функция/метод имеет тест, который:
1. Сначала упал по ожидаемой причине
2. Прошёл после минимальной реализации
3. Остаётся зелёным после рефакторинга
