# Brainstorming

**ЖЁСТКИЙ ЗАПРЕТ: никакого кода до согласования дизайна.**

## Процесс (строго по порядку)

1. **Изучи контекст** — просмотри релевантные файлы, последние коммиты, существующую архитектуру
2. **Задавай уточняющие вопросы** — по одному за раз, пока картина не прояснится
3. **Предложи 2–3 подхода** с trade-offs для каждого
4. **Представь дизайн** — по разделам, жди подтверждения каждого
5. **Запиши спецификацию** в `docs/specs/YYYY-MM-DD-<topic>.md`
6. **Self-review** — проверь спек на пробелы, противоречия, риски
7. **Пользователь утверждает спек** → только тогда переходим к планированию

## Выход из фазы

Brainstorming завершён, когда:
- Спек написан и утверждён пользователем
- Нет открытых вопросов
- Подход однозначно выбран
