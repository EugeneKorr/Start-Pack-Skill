Финализируй текущую сессию — передача дел новой сессии: $ARGUMENTS

Ты выполняешь /handoff-ingest: сессия тяжёлая по контексту, её закрываем. Задача — сохранить ценные знания в вики (с проверкой контролёром), записать состояние в HANDOFF и показать, сколько токенов экономит перенос. Это ВСЕГДА последнее действие сессии. Работай экономно: без длинных рассуждений, большие файлы не перечитывай — пиши по памяти сессии.

Рубильник: прежняя версия навыка — файл `~/.claude/commands/handoff-ingest.md.bak.*`, который оставляет `install.sh` (скопировать обратно в `handoff-ingest.md`), или история Start-Pack-Skill в git.

Инструменты: `M=~/.claude/tools/handoff/measure.py`. Текущая сессия определяется по `$CLAUDE_CODE_SESSION_ID` — НИКОГДА не бери «самый свежий .jsonl»: в одной папке работают несколько сессий.

## Шаг 0. Непрочитанная записка

Открой шапку `docs/HANDOFF.md`. Если «Статус: НЕ ПРИНЯТА» — предыдущую передачу ещё никто не забрал. Назови тему и дату той записки и спроси, перезаписывать ли (старая останется в git). «ПРИНЯТА» или файла нет — продолжай молча.

## Шаг 1. Замер

```bash
python3 $M stats                      # 1-я строка — токены/$, 2-я — лимиты подписки, 3-я — JSON
python3 $M dialog --out /tmp/handoff-dialog-$CLAUDE_CODE_SESSION_ID.md
```
Сохрани строки 1–2 — они пойдут в HANDOFF и в финальное сообщение. Из JSON возьми `last_ctx` и `models`.

**Режим записи вики** (для Шага 3): окно модели — 1 000 000 для Fable/Opus/Sonnet 5 и 4.6+, 200 000 для Haiku. `last_ctx` > 90% окна → режим «Б» (вики пишет агент), иначе режим «А» (пишешь ты сам).

## Шаг 2. Сортировщик тем → решение пользователя

Запусти агента (Agent, general-purpose, `run_in_background: false`). Промпт — самодостаточный:

> Ты сортировщик знаний сессии перед её закрытием. Прочитай очищенный разговор `/tmp/handoff-dialog-<ID>.md` целиком. Также: `git log --oneline --since="<начало сессии>"` в `<папка проекта>` и `gh pr list --state merged --limit 20` (смёрженный PR = «в проде»). Существующие страницы вики: `<папка>/wiki/index.cache.json` и `~/.claude/wiki/index.cache.json` (только заголовки и теги).
> Выдели темы сессии (решения, находки, настройки, грабли, отвергнутые варианты). Для каждой верни строку таблицы:
> | № | Тема (суть в 1 фразе) | Статус | Вклад | Куда | Предложение |
> Статус: 🟢 в проде/принято · 🟡 в работе · 🔴 отказались · ⚪ временное/мусор. Вклад: высокий/средний/низкий.
> Куда: «вики проекта: новая <slug>» / «вики проекта: дополнить <slug>» / «общая вики: …» (общая = бизнес в целом, связь проектов, аккаунты, инструменты для всех проектов) / «HANDOFF» / «—».
> Правила: 🟢 → сохранить; 🔴 → одна строка «рассматривали X, отказались, потому что Y» на странице темы; 🟡 → только HANDOFF; ⚪ → не сохранять. Не выдумывай — только то, что есть в разговоре и git. Если тема уже есть в вики — предлагай «дополнить», не новую страницу.

Покажи пользователю таблицу и спроси: «Сохраняю по таблице? Ответь „ок“ или поправь строки (например „3 не сохранять, 5 в общую“)». **Жди ответа** — дальше не иди.

## Шаг 3. Запись вики (по одобренной таблице)

Формат страниц — по `/wiki-ingest` (frontmatter: title, tags, created, updated, sources, scope, page_type, related; обновить `index.cache.json`, запись в `log.jsonl` с `"source": "handoff <sessionId>"`). Перед правкой страниц общей вики `~/.claude/wiki` (она не под git) — скопируй изменяемые файлы в `~/.claude/backups/wiki-<дата>/`.

- **Режим А:** пишешь сам по памяти сессии — у тебя есть и детали из вывода команд, которых нет в очищенном разговоре.
- **Режим Б:** запусти агента-писателя с одобренной таблицей, путём к очищенному разговору и теми же правилами формата; сам вики не пиши (риск автосжатия контекста).

## Шаг 4. Контролёр

Запусти агента (general-purpose, `run_in_background: false`):

> Ты контролёр полноты вики перед закрытием сессии. Даны: одобренная таблица тем (ниже), очищенный разговор `/tmp/handoff-dialog-<ID>.md`, изменения вики (`git -C <папка> diff HEAD -- wiki/` + новые файлы из `git status`, и страницы общей вики из `log.jsonl` с source «handoff <ID>»), черновик HANDOFF (ниже).
> Проверь: (1) каждая тема 🟢/🔴 из таблицы есть в вики с сутью (что решили, почему, где в коде/PR), а не одним заголовком; (2) каждый смёрженный PR сессии упомянут; (3) нет противоречий с тем, что уже было на странице; (4) 🟡 есть в HANDOFF. Верни список пропусков «тема → чего не хватает → куда дописать» или «пропусков нет». Не переписывай сам.

Пропуски дописывай сам (в режиме Б — через того же писателя) и сообщи одной строкой: «контролёр нашёл N пропусков — дописал». Если что-то дописать не удалось — пометка в HANDOFF «вики: есть пропуски: …».

## Шаг 7. Пометить этот чат «закрыт»

`f=$(python3 $M stats | tail -1 | jq -r .transcript)`; sessionId = `$CLAUDE_CODE_SESSION_ID`.
1. Текущее название — последняя запись `"type":"custom-title"` в `$f` (нет — придумай короткое по теме).
2. Сними с НАЧАЛА названия все эмодзи (1️⃣2️⃣3️⃣🚫 и др.; @ и текст не трогай), поставь «🚫 ». Пример: «1️⃣ @@@ parcel_delivery1» → «🚫 @@@ parcel_delivery1».
3. `printf '{"type":"custom-title","customTitle":"%s","sessionId":"%s"}\n' "<новое>" "$CLAUDE_CODE_SESSION_ID" >> "$f"`. Вкладка может обновиться после переоткрытия чата.

## Шаг 8. Коммит

`git add docs/HANDOFF.md docs/TODO.md wiki/ && git commit -m "docs(handoff): передача дел <тема> <дата> + вики"`. Push — только если ветка отслеживает origin; ошибку пуша не чини, просто сообщи.

## Шаг 9. Финальное сообщение (коротко, два абзаца + шаги)

1. «HANDOFF обновлён (коммит X, тема Y). <строка 1 замера>. <строка 2 — лимиты>.»
2. «Вики сохранена и проверена: N тем (<slug-и>); контролёр: <пропусков нет | дописал N>. Не сохранял: <⚪/🟡 кратко>.»
3. «Открой новый чат в этой же папке и запусти /handoff-query <приоритет 1/2/3>.»
