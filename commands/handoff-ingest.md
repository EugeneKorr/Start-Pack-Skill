Финализируй текущую сессию — передача дел новой сессии: $ARGUMENTS

Ты выполняешь /handoff-ingest: сессия близка к пределу контекста, твоя задача — сжато и без потерь записать состояние в файлы репозитория и закоммитить. Это ВСЕГДА последнее действие сессии. Работай ЭКОНОМНО по токенам: без длинных рассуждений, без перечитывания больших файлов — пиши по памяти сессии.

## Шаг 0. Проверь, не лежит ли в HANDOFF непрочитанная записка

Открой `docs/HANDOFF.md` (только шапку). Если файл существует и в нём «Статус: НЕ ПРИНЯТА» — предыдущую передачу ещё не прочитал новый чат (вероятно, другой тематики). Скажи пользователю тему и дату той записки и спроси, перезаписывать ли (старая останется в git-истории и восстановима). Если «ПРИНЯТА» или файла нет — перезаписывай молча.

## Шаг 1. Перезапиши docs/HANDOFF.md

Один живой файл-«записка сменщику», перезаписывается целиком (история — в git). Структура:

```markdown
# HANDOFF — <проект> · тема: <тема этой сессии>
Обновлено: <дата время> · ветка: <git branch>
Статус: НЕ ПРИНЯТА

## Транскрипт завершённой сессии (для wiki-ingest из новой сессии)
- путь: <САМЫЙ СВЕЖИЙ .jsonl — команда ниже>
- wiki-ingest: НЕ выполнен | выполнен <дата>

## Что сделано в этой сессии
- ...(сжато, с путями файлов и номерами PR/issues)

## В работе прямо сейчас
- задача, ТОЧНЫЙ текущий шаг, что уже попробовано

## Следующие шаги (по порядку)
1. ...

## Грабли и решения этой сессии (нельзя терять)
- ...

## Открытые вопросы (ждут Евгения/Володю/Романа)
- ...
```

Путь к транскрипту текущей сессии: `ls -t ~/.claude/projects/$(pwd | sed 's/[/_]/-/g')/*.jsonl | head -1` (самый свежий = текущая сессия).

## Шаг 2. Допиши docs/TODO.md

Незакрытые пункты сессии — дописать (не перезаписывать файл).

## Шаг 3. Пометка wiki-ingest — по ФАКТУ

Если пользователь хочет вики в старом чате — она делается ДО /handoff-ingest, ты здесь только фиксируешь факт. Определи, выполнялся ли /wiki-ingest в ЭТОЙ сессии (знаешь из хода сессии; для надёжности сверься с `wiki/log.jsonl`) и поставь пометку:
- выполнялся → «wiki-ingest: выполнен <дата время>» — новая сессия его НЕ повторит;
- нет → «wiki-ingest: НЕ выполнен» — его сделает новая сессия по транскрипту.

Сам /wiki-ingest отсюда НЕ запускай и не предлагай: при малом остатке контекста это риск словить автокомпакт.

## Шаг 3а. Переименуй этот чат (пометка «закрыт»)

Транскрипт текущей сессии: `f=$(ls -t ~/.claude/projects/$(pwd | sed 's/[/_]/-/g')/*.jsonl | head -1)`; sessionId = имя файла без .jsonl.
1. Текущее название: последняя запись `"type":"custom-title"` в этом файле (если нет — придумай короткое из темы сессии).
2. Сними с НАЧАЛА названия все эмодзи (1️⃣2️⃣3️⃣🚫 и любые другие; символы @ и текст не трогай) и поставь в начало «🚫 ». Пример: «1️⃣ @@@ parcel_delivery1» → «🚫 @@@ parcel_delivery1».
3. Допиши в конец транскрипта строку (ровно этот формат): `printf '{"type":"custom-title","customTitle":"%s","sessionId":"%s"}\n' "<новое>" "<sessionId>" >> "$f"`.
4. В HANDOFF.md добавь строку в шапку: «Название чата (база): <название без эмодзи и без ведущих @>» — его возьмёт /handoff-query для нового чата.

Примечание: вкладка может показать новое имя не сразу, а после переоткрытия чата — это нормально.

## Шаг 4. Закоммить

`git add docs/HANDOFF.md docs/TODO.md && git commit -m "docs(handoff): передача дел <тема> <дата>"`. Push — только если ветка уже отслеживает origin; при ошибке пуша не останавливайся, просто скажи.

## Шаг 5. Финальное сообщение пользователю (коротко)

«HANDOFF обновлён (коммит X, тема Y). Открой новый чат в этой же папке и запусти /handoff-query — он примет передачу и сделает wiki-ingest старой сессии.»
