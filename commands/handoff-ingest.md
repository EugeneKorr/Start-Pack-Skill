Финализируй текущую сессию — передача дел новой сессии: $ARGUMENTS

Ты выполняешь /handoff-ingest «слепок»: сессия тяжёлая по контексту, её закрываем. Цель — сохранить знания в вики (с проверкой контролёром) и записать состояние в записку, потратив как можно меньше обращений с полным контекстом. Это ВСЕГДА последнее действие сессии.

**Главное правило экономии:** каждое твоё действие (каждый вызов инструмента) — отдельное обращение к модели с полным контекстом. Поэтому всё, что можно, делают агенты со свежим контекстом, а ты делаешь ровно эти шаги: 1 вызов `prep` → 1 запуск сортировщика → показать таблицу и ждать «ок» → 1 запись слепка → 1 запуск раскладчика → 1 запуск контролёра → 1 сообщение раскладчику с пропусками (если есть) → финальный ответ. Никаких чтений файлов «на всякий случай», никаких промежуточных правок своими руками.

Инструменты: `M=~/.claude/tools/handoff/measure.py` (ставится `install.sh` из Start-Pack-Skill). Сессия определяется по `$CLAUDE_CODE_SESSION_ID` — НИКОГДА не бери «самый свежий .jsonl»: в папке работают несколько сессий. Время — только из `date '+%Y-%m-%d %H:%M'`, не по памяти.

Рубильник: прежняя версия — `~/.claude/commands/handoff-ingest.md.bak.*` (оставляет `install.sh`) или история Start-Pack-Skill.

## Шаг 1. Подготовка — один вызов

```bash
python3 $M prep
```
Печатает: ЗАМЕР и ЛИМИТЫ (пойдут в записку и финал), РЕЖИМ (А/Б), ПАПКУ `~/.claude/handoff/<ID>/` с `dialog.md` (очищенный разговор), `context.md` (коммиты с начала сессии, смёрженные PR, заголовки вики проекта и общей), `stats.json`; ЧАТ (название, база, slug нити, формат записок) и шапку текущей записки.

- **Формат записок.** Есть папка `docs/handoff/` → записка нити `docs/handoff/<slug>.md`, оглавление `docs/HANDOFF.md`. Нет папки → старый формат, один файл `docs/HANDOFF.md`. Папку сам не создавай — это решение проекта.
- **Непринятая записка.** Если в шапке записки «Статус: НЕ ПРИНЯТА» — её ещё никто не забрал. Назови тему и дату и спроси, перезаписывать ли (старая останется в git). Иначе продолжай.
- **Режим Б** (контекст выше 90% окна): слепок пишет не ты, а агент по `dialog.md` — см. Шаг 3.

## Шаг 2. Сортировщик → решение пользователя

Запусти агента: `Agent`, `subagent_type: general-purpose`, **`model: sonnet`**, `run_in_background: false`. Промпт самодостаточный — агент ничего о сессии не знает:

> Ты сортировщик знаний сессии перед её закрытием. Прочитай целиком `<ПАПКА>/dialog.md` (разговор) и `<ПАПКА>/context.md` (коммиты, PR, существующие страницы вики). Смёрженный PR = «в проде».
> Выдели темы (решения, находки, настройки, грабли, отвергнутые варианты). Для каждой — строка таблицы:
> | № | Тема (суть в 1 фразе) | Статус | Вклад | Куда | Предложение |
> Статус: 🟢 в проде/принято · 🟡 в работе · 🔴 отказались · ⚪ временное/мусор. Вклад: высокий/средний/низкий.
> Куда: «вики проекта: дополнить <slug>» / «вики проекта: новая <slug>» / «общая вики: …» (общая = бизнес в целом, связь проектов, аккаунты, инструменты для всех проектов) / «записка» / «—».
> Правила: 🟢 → сохранить; 🔴 → одна строка «рассматривали X, отказались, потому что Y» на странице темы; 🟡 → только записка; ⚪ → не сохранять. Тема уже есть в вики → «дополнить», не новая страница. Не выдумывай — только то, что есть в файлах. Верни только таблицу и под ней список 🟡 для записки.

Покажи таблицу пользователю и спроси: «Сохраняю по таблице? Ответь „ок“ или поправь строки (например „3 не сохранять, 5 в общую“)». **Жди ответа.**

## Шаг 3. Слепок — одна запись

По одобренной таблице запиши ОДНИМ вызовом `Write` файл `<ПАПКА>/dump.md`. Это всё, что ты знаешь и что нужно сохранить; дальше тебя не будет. Пиши по памяти сессии, включая детали из вывода команд, которых нет в `dialog.md` (пути, номера миграций, точные команды, значения настроек). Структура:

```markdown
# Слепок сессии <ID> · нить: <база> · <дата время из date>

## Записка
### Что сделано в этой сессии
### В работе прямо сейчас (задача, ТОЧНЫЙ шаг, что пробовали) — сюда темы 🟡
### Следующие шаги (по порядку)
### Грабли и решения (нельзя терять)
### Открытые вопросы (кто должен ответить)
### Модель для следующей сессии: <fable|opus|sonnet> — <почему: тип работы в нити>

## Вики
### <slug> · <проект|общая> · <дополнить|новая> · темы №…
<готовый текст для страницы: что решили, почему, где в коде/PR/миграции; для 🔴 — строка «рассматривали X, отказались, потому что Y»>
### <следующая страница> …

## TODO (дописать в docs/TODO.md)
- …
```

Секретов (пароли, токены, ключи, личные документы) в слепке быть не должно — замени на «<в .env>» / «<в private/>». В **режиме Б** вместо записи сам запусти агента-писателя (sonnet): дай ему таблицу, `dialog.md`, `context.md` и эту же структуру — пусть напишет `dump.md`; ты его не читай.

## Шаг 4. Раскладчик — один запуск

`Agent`, general-purpose, **`model: sonnet`**, `run_in_background: false`. Промпт:

> Ты раскладчик слепка сессии. Исходник — `<ПАПКА>/dump.md` (истина), контекст — `<ПАПКА>/context.md`, замер — `<ПАПКА>/stats.json`. Проект: `<папка проекта>`, нить `<slug>`, формат `<по нитям | один файл>`.
> 1. Рабочая копия: `cd <проект> && git fetch -q 2>/dev/null; base=$(git rev-parse -q --verify origin/main >/dev/null && echo origin/main || echo main); git worktree add -q ../<проект>-handoff-<ID8> -b docs/handoff-<slug>-<дата> $base`. Все правки — там. Ветки в основной папке не трогай.
> 2. Вики по секции «## Вики»: формат страниц как в /wiki-ingest (frontmatter title, tags, created, updated, sources, scope, page_type, related; обновить `index.cache.json`; строка в `log.jsonl` с `"source": "handoff <ID>"`). Страницы общей вики `~/.claude/wiki` правь на месте, перед правкой копия в `~/.claude/backups/wiki-<дата>/`. Если в `log.jsonl` уже есть запись «handoff <ID>» — это повтор после сбоя: не дублируй, только допиши недостающее.
> 3. Записка из секции «## Записка». Шапка:
> `# HANDOFF — <проект> · нить: <база> · тема: <тема>` / `Обновлено: <date> · ветка: main` / `Статус: НЕ ПРИНЯТА` / `Название чата (база): <база>` / раздел «## Вики и замер»: строка «вики: разложена, проверка: ожидается», ЗАМЕР, ЛИМИТЫ, «стартовый контекст новой сессии: (заполнит /handoff-query)», «слепок: <ПАПКА>/dump.md», «модель для следующей сессии: …». Формат по нитям → `docs/handoff/<slug>.md` + строка нити в оглавлении `docs/HANDOFF.md` (таблица: нить · файл · статус · обновлено). Один файл → перезапиши `docs/HANDOFF.md`.
> 4. `docs/TODO.md` — дописать пункты из «## TODO», не перезаписывать.
> 5. Перед коммитом проверь diff на секреты: `git diff --cached | grep -niE 'password|passwd|token|secret|api[_-]?key|sk-|BEGIN (RSA|OPENSSH)|IBAN'` — нашёл → замени на «<в .env>» и скажи об этом в отчёте.
> 6. Коммит `docs(handoff): передача дел <нить> <дата> + вики`, push, `gh pr create`, дождись зелёного CI, `gh pr merge --squash`; worktree удали (`git worktree remove`). Нет origin/gh → только коммит в worktree-ветку и скажи.
> 7. Создай `<ПАПКА>/done` с номером PR. Отчёт: страницы вики (slug → что добавлено), путь записки, PR, что заменил как секрет.

## Шаг 5. Контролёр — один запуск

`Agent`, general-purpose, **`model: sonnet`**, `run_in_background: false`:

> Ты контролёр полноты. Даны: `<ПАПКА>/dump.md` (что должно быть сохранено), `<ПАПКА>/dialog.md` (что обсуждали), изменения в вики и записке: `git -C <проект> log -1 --stat origin/main` после PR #<N> (или `git show <коммит>`), плюс страницы общей вики по `log.jsonl` с source «handoff <ID>».
> Проверь: (1) каждая секция «## Вики» слепка попала на свою страницу с сутью, а не заголовком; (2) каждый 🟢/🔴 пункт одобренной таблицы (ниже) есть; (3) смёрженные PR сессии из `context.md` упомянуты; (4) 🟡 есть в записке; (5) новое не противоречит старому на той же странице; (6) в разговоре нет решений, которых нет ни в слепке, ни в вики. Верни список «пропуск → куда дописать → текст» или «пропусков нет». Сам ничего не правь.

Пропуски есть → `SendMessage` раскладчику (тот же агент, контекст сохранён): «Допиши: …, тем же путём через worktree и PR, затем обнови `done`». Затем в записке строка «вики: разложена, проверена (контролёр: N пропусков дописано)» — это тоже делает раскладчик в том же сообщении. Пропусков нет → раскладчику сообщение «проверка пройдена, поставь в записке „проверена“» (одна правка, тот же PR-поток).

## Шаг 6. Пометить чат закрытым и доложить

Пометка «🚫» — один вызов:
```bash
f=$(jq -r .transcript <ПАПКА>/stats.json); t=$(grep -o '"customTitle":"[^"]*"' "$f" | tail -1 | cut -d'"' -f4)
new="🚫 $(python3 -c "import sys,re;print(re.sub(r'^(?:[0-9]️?⃣|[^\w@])+','',sys.argv[1]).strip())" "$t")"
printf '{"type":"custom-title","customTitle":"%s","sessionId":"%s"}\n' "$new" "$CLAUDE_CODE_SESSION_ID" >> "$f"
```
(нет названия → `🚫 <база или имя проекта>`; вкладка обновится после переоткрытия).

Финальное сообщение (коротко):
1. «Записка обновлена: <путь>, PR #N. <ЗАМЕР>. <ЛИМИТЫ>.»
2. «Вики сохранена и проверена: N страниц (<slug-и>); контролёр: <пропусков нет | дописано N>. Не сохранял: <⚪/🟡 кратко>.»
3. «Открой новый чат в этой же папке → `/handoff-query <приоритет 1/2/3>`; рекомендуемая модель для нити — `/model <…>`.»
