Финализируй текущую сессию — передача дел новой сессии: $ARGUMENTS

Ты выполняешь /handoff-ingest «слепок»: сессия тяжёлая по контексту, её закрываем. Цель — сохранить знания в вики (с проверкой контролёром) и записать состояние в записку, потратив как можно меньше обращений с полным контекстом. Это ВСЕГДА последнее действие сессии.

**Без вопросов пользователю (с 17.11.2026).** Набранная команда — это уже согласие на всё: таблицу сортировщика, сохранение в вики, записку, PR и мердж. Ничего не спрашивай и «ок» не жди — от начала до финального ответа без остановок. Сессия закрыта сразу после финального ответа. Рубильник: вернуть из `.bak` версию со строкой «показать таблицу и ждать „ок“».

**Главное правило экономии:** каждое твоё действие (каждый вызов инструмента) — отдельное обращение к модели с полным контекстом. Поэтому всё, что можно, делают агенты со свежим контекстом, а ты делаешь ровно эти шаги: 1 вызов `prep` (+ снять прогрев, если был) → 1 запуск сортировщика → 1 запись слепка → 1 запуск раскладчика → 1 запуск контролёра → 1 сообщение раскладчику с пропусками (если есть) → финальный ответ. Никаких чтений файлов «на всякий случай», никаких промежуточных правок своими руками.

Инструменты: `M=~/.claude/tools/handoff/measure.py` (ставится `install.sh` из Start-Pack-Skill). Сессия определяется по `$CLAUDE_CODE_SESSION_ID` — НИКОГДА не бери «самый свежий .jsonl»: в папке работают несколько сессий. Время — только из `date '+%Y-%m-%d %H:%M'`, не по памяти.

Рубильник: прежняя версия — `~/.claude/commands/handoff-ingest.md.bak.*` (оставляет `install.sh`) или история Start-Pack-Skill.

## Шаг 2. Сортировщик

Запусти агента: `Agent`, `subagent_type: general-purpose`, **`model: sonnet`**, `run_in_background: false`. Промпт самодостаточный — агент ничего о сессии не знает:

> Ты сортировщик знаний сессии перед её закрытием. Прочитай целиком `<ПАПКА>/dialog.md` (разговор) и `<ПАПКА>/context.md` (коммиты, PR, существующие страницы вики). Смёрженный PR = «в проде».
> Выдели темы (решения, находки, настройки, грабли, отвергнутые варианты). Для каждой — строка таблицы:
> | № | Тема (суть в 1 фразе) | Статус | Вклад | Куда | Предложение |
> Статус: 🟢 в проде/принято · 🟡 в работе · 🔴 отказались · ⚪ временное/мусор. Вклад: высокий/средний/низкий.
> Куда: «вики проекта: дополнить <slug>» / «вики проекта: новая <slug>» / «общая вики: …» (общая = бизнес в целом, связь проектов, аккаунты, инструменты для всех проектов) / «записка» / «—».
> Правила: 🟢 → сохранить; 🔴 → одна строка «рассматривали X, отказались, потому что Y» на странице темы; 🟡 → только записка; ⚪ → не сохранять. Тема уже есть в вики → «дополнить», не новая страница. Не выдумывай — только то, что есть в файлах. Верни только таблицу, под ней список 🟡 для записки и блок «Попытки по цели».
> Блок «Попытки по цели»: если в сессии одну и ту же цель (починить X, пройти порог Y) пытались достичь отдельными подходами, доведёнными до результата (замер, тест, выкатка), — строка на каждую: «цель — попытка → удача / неудача (критерий, записанный до попытки, не пройден, или проблема вернулась)». Шаги одного плана — не отдельные попытки. Не смягчай: «порог не пройден» — это неудача, даже если «стало лучше». Таких целей нет — «попыток по одной цели не было».

Таблицу пользователю не показывай и не спрашивай — она принимается как есть (счёт попыток свежего агента сам не занижай). Сразу переходи к Шагу 3.

## Шаг 3. Слепок — одна запись

По таблице сортировщика запиши ОДНИМ вызовом `Write` файл `<ПАПКА>/dump.md`. Это всё, что ты знаешь и что нужно сохранить; дальше тебя не будет. Пиши по памяти сессии, включая детали из вывода команд, которых нет в `dialog.md` (пути, номера миграций, точные команды, значения настроек). Структура:

```markdown
# Слепок сессии <ID> · нить: <база> · <дата время из date>
Ключевое слово: <слово>

## Записка
### Что сделано в этой сессии
### В работе прямо сейчас (задача, ТОЧНЫЙ шаг, что пробовали) — сюда темы 🟡
### Попытки по цели
Цель: <одной фразой>. Попыток N, неудачных M (вместе с прошлыми сессиями). Перечень: <дата · попытка → итог одной строкой>. Взгляд сверху или штурм: <дата> / не было.
### Следующие шаги (по порядку)
### Грабли и решения (нельзя терять)
### Открытые вопросы (кто должен ответить)
### Модель для следующей сессии: <fable|opus|sonnet> — <почему: тип работы в нити>

## Вики
### <slug> · <проект|общая> · <дополнить|новая> · темы №…
<готовый текст для страницы: что решили, почему, где в коде/PR/миграции; для 🔴 — строка «рассматривали X, отказались, потому что Y»>
### <следующая страница> …

## TODO (дописать в docs/TODO.md)
- …
```

**Ключевое слово записки** (с 17.11.2026) — одно короткое слово латиницей в нижнем регистре, 3–12 букв, по теме нити (`sla`, `warm`, `deklar`). По нему новая сессия выбирает записку: `/handoff-query 1 <слово>`. В текущей записке нити уже есть «Ключевое слово:» — оставь то же; нет — придумай, не совпадающее со словами других записок проекта (в формате по нитям — короткая форма slug).

**«Попытки по цели» — счётчик против хождения по кругу** (с 17.11.2026). Круг обычно размазан по нескольким сессиям: каждая получает записку «следующий шаг — вариант X» и видит только свою попытку. Прошлые числа возьми из того же раздела текущей записки нити (раздела нет — посчитай по записке и `docs/TODO.md` и пометь «оценка»), прибавь попытки этой сессии из блока сортировщика. Цель достигнута или сменилась — напиши «попыток по одной цели нет» и начни счёт заново. Рубильник: убрать раздел из структуры и этот абзац.

Секретов (пароли, токены, ключи, личные документы) в слепке быть не должно — замени на «<в .env>» / «<в private/>». В **режиме Б** вместо записи сам запусти агента-писателя (sonnet): дай ему таблицу, `dialog.md`, `context.md` и эту же структуру — пусть напишет `dump.md` (прошлые «Попытки по цели» он читает из записки нити сам); ты его не читай.

## Шаг 4. Раскладчик — один запуск

`Agent`, general-purpose, **`model: sonnet`**, `run_in_background: false`. Промпт:

Страницы общей вики `~/.claude/wiki` правь на месте, перед правкой копия в `~/.claude/backups/wiki-<дата>/`.
