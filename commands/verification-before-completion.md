Проверь, прежде чем заявить «готово»: $ARGUMENTS

Железное правило: никаких «готово», «починил», «тесты проходят», «работает» без свежего доказательства, полученного в ЭТОМ ответе.

Перед любым заявлением об успехе:
1. **Определи**, какая команда или проверка доказывает утверждение.
2. **Запусти** её целиком и заново. Прошлый запуск и «должно пройти» не считаются.
3. **Прочитай** вывод полностью: код возврата, число падений.
4. **Сверь**: вывод подтверждает утверждение? Нет — назови реальное состояние с доказательством. Да — заяви результат и приложи доказательство.

Чем доказывать:

| Утверждение | Доказательство | Не доказательство |
|---|---|---|
| Тесты проходят | Вывод тестов: 0 падений | Прошлый запуск, «должно пройти» |
| Сборка/старт работают | Команда сборки или смоук старта: exit 0 | Прошёл линтер |
| Баг исправлен | Исходный симптом воспроизведён и больше не воспроизводится | «Код поменян» |
| Регрессионный тест рабочий | Красный → зелёный: откат фикса роняет тест | Тест прошёл один раз |
| Вёрстка/интерфейс в порядке | Сам посмотрел скриншот или страницу | «CSS выглядит верно» |
| Настройка прода применилась | Запрос к эндпоинту или SQL-замер (только чтение) | Дашборд, «задеплоилось» |
| Субагент сделал работу | `git diff` показывает изменения, проверены руками | Отчёт агента «успех» |
| Требования выполнены | Перечитал план/спек, отметил каждый пункт | «Тесты зелёные» |

Красные флаги — остановись: «должно», «вероятно», «похоже», радость до проверки («Готово!», «Отлично!»), коммит/push/PR без проверки, «один раз можно».

Если проверить нельзя (нет доступа, нужен прод) — так и скажи: что проверено, что нет и чем это проверить.
