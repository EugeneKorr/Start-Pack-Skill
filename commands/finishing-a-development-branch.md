Заверши ветку разработки: $ARGUMENTS

Порядок: проверки → базовая ветка → варианты → выполнение выбора → уборка.

**1. Проверки.** Запусти полный набор тестов проекта и смоук старта, если он есть. Красное — покажи падения и остановись, меню только после зелёного. Затем `/code-review`, при чувствительном диффе (TEAM-RULES, контрольные точки) — `/security-review`.

**2. Базовая ветка.** Определи, от какой ветки отошли (план, разговор, upstream). Не уверен — спроси: «Ветка отошла от <догадка>, верно?».

**3. Предложи ровно эти варианты и жди ответа:**
```
Работа готова. Что делаем?
1. Push и PR в <base>  ← по умолчанию
2. Оставить ветку как есть (займусь позже)
3. Влить в <base> локально
```
Вариант 3 — только для репо без автодеплоя. В экосистеме Vega (`vega-exchange-`, `vega-rates-calculator`, `vega-services`, `crm`) push в `main` = деплой: там только PR и мерж по явной команде.

**4. Выполнение.**
- *PR:* `git push -u origin <ветка>`, PR по шаблону репо, ссылку — пользователю. Ветку и worktree не трогаем: правки по ревью идут там.
- *Оставить:* «Ветка <имя> сохранена, worktree: <путь>».
- *Локальный мерж:* `git checkout <base> && git pull && git merge <ветка>`, затем тесты на слитом результате. Красное — стоп, ветку не удалять. Зелёное — `git branch -d <ветка>`.

**5. Уборка worktree** — только после локального мержа или подтверждённого удаления, и только для worktree, созданных нами (`.worktrees/`, `worktrees/`). Отказ удаления из-за незакоммиченных файлов — показать список и спросить, `--force` самому никогда.

Удалить работу — только если пользователь прямо попросил и набрал слово `discard`. Отклонённый push — разобраться, force-push только по явной просьбе.
