Прими передачу дел от предыдущей сессии и введи себя в контекст: $ARGUMENTS

Ты выполняешь /handoff-query — первый запуск новой сессии после /handoff-ingest. Аргументы: приоритет `1|2|3` и, при формате по нитям, имя нити (slug или часть названия), например `/handoff-query 1 osnovnaya`.

Инструменты: `M=~/.claude/tools/handoff/measure.py`. Транскрипт ТЕКУЩЕЙ сессии — по `$CLAUDE_CODE_SESSION_ID`, никогда не «самый свежий .jsonl». Время — из `date`.
Рубильник: `~/.claude/commands/handoff-query.md.bak.*` (оставляет `install.sh`) или история Start-Pack-Skill.

## Шаг 1. Подтяни main и посмотри, что принимать

```bash
git pull --ff-only -q 2>&1 | tail -1; python3 $M query-prep
```
Печатает: формат (по нитям / один файл), все записки с их статусами, стартовый контекст этой сессии и **неразложенные слепки** этого проекта (агент-раскладчик прошлой сессии упал или сессию закрыли раньше).

- Одна записка «НЕ ПРИНЯТА» → бери её. Несколько → выбери по аргументу; аргумента нет → один вопрос «Какую нить принимаем: …?».
- Все «ПРИНЯТА» → скажи, покажи `git log --oneline -5 -- docs/HANDOFF.md docs/handoff/` и спроси, поднять ли версию из истории.
- Записок нет → скажи прямо, предложи собрать контекст из git log + TODO + wiki; состояние не выдумывай.

## Шаг 1а. Неразложенный слепок → доразложи

Если `query-prep` показал «СЛЕПОК НЕ РАЗЛОЖЕН» для выбранной нити — запусти раскладчика (`Agent`, general-purpose, `model: sonnet`) с промптом из Шага 4 `/handoff-ingest` (исходник `dump.md`, worktree, вики, записка, PR, файл `done`), затем контролёра (Шаг 5 там же). Это дёшево: контекст свежий. Слепок другой нити — не трогай, только упомяни в докладе.

## Шаг 2. Прочитай записку

1. Записка нити (`docs/handoff/<slug>.md`) или `docs/HANDOFF.md` — главный источник: состояние, следующий шаг, грабли, открытые вопросы, **рекомендуемая модель**.
2. `docs/TODO.md` — открытые задачи.
3. `git log --oneline -15` и `git status --short --branch`.
4. CLAUDE.md проекта подхватывается автоматически.

Раздел «Вики и замер»: «разложена, проверена» — хорошо. «проверка: ожидается», «есть пропуски» или строки нет (записка старого формата) — ГРОМКО предупреди в докладе, что знания могли не попасть в вики, и дай путь к слепку/транскрипту. Ingest без команды пользователя не запускай.

## Шаг 2а. Название этого чата

Приоритет — из аргумента (1/2/3 → 1️⃣ 2️⃣ 3️⃣); нет — один вопрос «Приоритет 1/2/3?». Название: «<эмодзи> <Название чата (база) из записки>».
```bash
f=$(python3 $M stats | tail -1 | jq -r .transcript)
printf '{"type":"custom-title","customTitle":"%s","sessionId":"%s"}\n' "<название>" "$CLAUDE_CODE_SESSION_ID" >> "$f"
```

## Шаг 2б. Подтяни вики по теме записки

Шаг 2 проверял, СОХРАНИЛА ли старая сессия свои знания. Этот шаг — другое: ВСПОМНИТЬ, что уже лежит в вики по теме (грабли и решения прошлых сессий, в том числе давних), до начала работы. Если в проекте есть `wiki/` — выполни /wiki-query по теме и следующему шагу из записки (одна формулировка, 3–6 ключевых слов). Нужны находки, а не пересказ. Нет `wiki/` или ничего релевантного — пропусти и отметь в докладе.

## Шаг 3. Погаси записку

- «Статус: НЕ ПРИНЯТА» → «Статус: ПРИНЯТА <date>»; в формате по нитям — и статус в строке нити в `docs/HANDOFF.md`.
- «стартовый контекст новой сессии» → факт из `query-prep` (в тыс. токенов).
- Коммит `docs(handoff): передача принята — <нить>` и push (ветка отслеживает origin). Отклонён push → `git pull --ff-only` и повтор; никаких reset.

## Шаг 4. Доложи и жди задачу

Сжато (6–9 строк):
- состояние одним абзацем;
- что в работе и ТОЧНЫЙ следующий шаг;
- открытые вопросы, требующие решения;
- вики: «разложена и проверена старой сессией (N страниц)» или предупреждение из Шага 2;
- что нашлось в вики по теме (1–3 пункта со ссылками на страницы) или «по теме ничего»;
- экономия: «старая сессия ~X тыс. на вопрос → эта стартовала с ~Y тыс.»;
- **модель:** «для этой нити рекомендована `/model <…>` (<почему>); сейчас сессия на <модель из stats>» — переключить может только пользователь.

НЕ начинай следующий шаг из записки без явной команды пользователя.
