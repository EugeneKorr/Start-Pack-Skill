Начни с заголовка:
```
# [Feature] Implementation Plan
**Цель:** [одно предложение]
**Архитектура:** [2–3 предложения]
**Стек:** [ключевые технологии]
```

Для каждого шага плана обязательно укажи:
- Точные пути к файлам которые нужно создать или изменить
- Полный код (не заглушки и не "реализуй похожим образом")
- Конкретную команду для проверки что шаг выполнен
- Критерий завершения

Запрещено использовать: TBD, TODO, "implement later", "appropriate error handling", "similar to Task N", "и так далее".

Перед финальной версией плана проверь:
- [ ] Все шаги покрывают согласованный дизайн полностью
- [ ] Нет ни одного плейсхолдера
- [ ] Типы данных согласованы между шагами
- [ ] Порядок шагов учитывает зависимости
- [ ] Для каждого нового механизма перечислено, с каким существующим он может
      конфликтовать, и как они разведены

## Точка Б — self-review плана свежим рецензентом (с 03.11.2026)

Чек-лист выше — проверка автора. Перед `/executing-plans` план проходит ещё одну проверку **чужими глазами и запуском**
(приём из parcel_delivery 28.10.2026, `docs/plans/2026-10-28-support-automation-crm/self-review.md`; в study-funnel —
исполнение агентом в worktree с 20.10). Пять правил:

1. **Рецензент — отдельный агент (`Agent`, general-purpose, не fork), которому даётся только путь к плану и спеку** —
   без выводов, чек-листа и переписки автора: с якорем он повторяет уже найденное.
2. **Код плана переносится дословно** в копию репозитория (`git worktree add -b review/<тема> .claude/worktrees/<тема> main`,
   символические ссылки на `node_modules` и `.env*`), прогоняются типы, тесты, проверка Deno, тесты базы на стенде проекта.
   Боевая база — только чтение (один запрос на реальных данных, если план что-то считает по ним).
3. **Отчёт — `docs/plans/<план>/self-review.md`** рядом с планом: 🔴 сломает исполнение или прод · 🟡 риск или неточность ·
   ⚪ мелочи · ✅ счёл верным. **К каждой находке — готовая замена** (какую строку плана на какую), не «подумать».
   Отдельно: **«Не проверялось запуском»** — честный список.
4. **Продуктовые вопросы — отдельным блоком «Решения Евгения»** с вариантами и ценой; технические правки автор вносит
   сам, продуктовые — только после ответа (вопросы — через `AskUserQuestion`).
5. **Правки возвращаются в план**, в `self-review.md` — таблица «где что исправлено» со статусом; если контекст автора
   на пределе — правки вносит новая сессия после `/handoff-ingest`.

Промпт рецензенту — по образцу:
«Проверь план <путь> по спеку <путь> в репозитории <путь>: перенеси код всех шагов дословно в worktree, прогони
<команды проверки из плана>, сверь каждый путь, имя, колонку и сигнатуру с кодом `main`. Отчёт запиши в <путь self-review.md>
в формате: 🔴/🟡/⚪/✅, у каждой находки — шаг плана, что не так, готовая замена; раздел «Не проверялось запуском»;
раздел «Вопросы, требующие решения Евгения» с вариантами. Боевая база — только чтение. План не правь.»
