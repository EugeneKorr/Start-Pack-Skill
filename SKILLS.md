# Каталог скиллов команды

Один документ на все наши slash-команды и скиллы: что делает, как устроен, как
запускать. Новый скилл появился в паке — сюда добавляется его секция. Этот файл
только дополняем, механику скилла описываем так, чтобы второй человек понял её
из одной короткой секции, не читая исходник.

---

## Установка — одна инструкция для всех скиллов

Скилл = обычный `.md`-файл с инструкцией для Claude. Имя файла = имя команды
(`handoff-ingest.md` → `/handoff-ingest`). Устанавливается копированием в
`~/.claude/commands/` — install.sh делает это за тебя:

1. Первый раз: `git clone https://github.com/EugeneKorr/Start-Pack-Skill.git ~/start-pack-skill`
2. `cd ~/start-pack-skill && ./install.sh` — скопирует все команды, старые версии сохранит в `.bak`.
3. Команды доступны во всех проектах. В уже открытом чате новая команда может не подхватиться — открой новый чат.

**Тебе прислали новый скилл (или обновили старый):** `cd ~/start-pack-skill && git pull && ./install.sh`. Всё.

**Ты сделал новый скилл и хочешь поделиться:** положи `.md` в `commands/` этого
репозитория, допиши секцию сюда в SKILLS.md, закоммить и запушь. Партнёр
получает его через `git pull && ./install.sh`.

## Процессные команды (основа TEAM-RULES)

### /brainstorming <задача>
Дизайн до кода. Изучает контекст проекта → задаёт уточняющие вопросы → предлагает
2–3 подхода с трейдоффами → фиксирует согласованный спек в `docs/specs/`.
Правило: никакого кода до утверждения спека. Для крупных и средних задач — вход
всегда отсюда (TEAM-RULES §1).

### /writing-plans <спек>
Из утверждённого спека делает детальный план реализации в `docs/plans/`: точные
пути файлов, готовый код шагов, критерий проверки каждого шага. Запрещены
заглушки и «доработаем позже».

### /executing-plans <план>
Исполняет план шаг за шагом: после каждого шага — верификация из плана, при
несовпадении — стоп и доклад, а не импровизация.

### /systematic-debugging <проблема>
Отладка через первопричину: воспроизведение → гипотезы → проверка по логам/коду →
только потом фикс. Запрещает «попробуем поменять и посмотреть».

### /tdd <фича>
Красный → зелёный → рефакторинг: сначала падающий тест, затем минимальный код,
затем чистка.

### /init
Сканирует репозиторий и создаёт/обновляет его `CLAUDE.md` (контекст проекта для
всех будущих сессий).

## Вики (память проекта)

### /wiki-ingest <источник>
Сохраняет знания в `wiki/` проекта. Источник: пусто/`session` — текущая сессия
(авто-суммаризация), путь — файл (в т.ч. `.jsonl`-транскрипт другого чата),
http(s) — ссылка. Флаг `--global` пишет в `~/.claude/wiki/` вместо проектной.
Обновляет `index.cache.json` и `log.jsonl` — по ним работает поиск.

### /wiki-query <вопрос>
Отвечает по накопленной вики: ищет релевантные страницы по индексу, читает их и
собирает ответ со ссылками на страницы. Не выдумывает: чего нет в вики — так и
говорит.

## Передача контекста между чатами (handoff)

Зачем: чат раздулся → каждый запрос дорогой, впереди автокомпакт с
неконтролируемой потерей деталей. Вместо этого — «записка сменщику»:
`docs/HANDOFF.md`, один живой файл на проект, перезаписывается при каждой
передаче (история в git). Цикл: в старом чате `/handoff-ingest` (всегда
ПОСЛЕДНЕЕ действие) → открываешь новый чат → `/handoff-query`.

### /handoff-ingest
Финализация закрываемого чата:
1. Если в `docs/HANDOFF.md` лежит ещё не принятая записка другого чата — предупредит, не затрёт молча.
2. Перезаписывает `docs/HANDOFF.md`: что сделано / в работе (точный шаг) / следующие шаги / грабли / открытые вопросы + путь к `.jsonl`-транскрипту сессии и пометка, делался ли `/wiki-ingest` (по факту).
3. Дописывает `docs/TODO.md`, коммитит.
4. Переименовывает закрываемый чат: снимает эмодзи с начала названия, ставит «🚫 ».
Вики из него не запускает (мало контекста — риск автокомпакта): её сделает новая сессия.

### /handoff-query [приоритет 1|2|3]
Первая команда нового чата:
1. Читает `docs/HANDOFF.md` + `docs/TODO.md` + `git log`. Если записка уже помечена «ПРИНЯТА» — предупредит и предложит поднять нужную версию из git-истории.
2. Если вики по старой сессии не делалась — сам запускает `/wiki-ingest <транскрипт>` (файл ≥2 МБ — спросит).
3. «Гасит» записку (Статус: ПРИНЯТА) и коммитит.
4. Переименовывает новый чат: «<1️⃣|2️⃣|3️⃣> <имя>» — приоритет из аргумента или спросит.
5. Докладывает состояние в 5–8 строк и ждёт задачу.
