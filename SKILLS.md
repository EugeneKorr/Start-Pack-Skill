# Каталог скиллов команды

Один документ на все наши slash-команды и скиллы: что делает, как устроен, как
запускать. Новый скилл появился в паке — сюда добавляется его секция. Этот файл
только дополняем, механику скилла описываем так, чтобы второй человек понял её
из одной короткой секции, не читая исходник.

---

## Установка — одна инструкция для всех скиллов

Скилл = обычный `.md`-файл с инструкцией для Claude. Имя файла = имя команды
(`handoff-ingest.md` → `/handoff-ingest`). Устанавливается копированием в
`~/.claude/commands/` — install.sh делает это за тебя:

1. Первый раз: `git clone https://github.com/EugeneKorr/Start-Pack-Skill.git ~/start-pack-skill`
2. `cd ~/start-pack-skill && ./install.sh` — скопирует все команды, старые версии сохранит в `.bak`.
3. Команды доступны во всех проектах. В уже открытом чате новая команда может не подхватиться — открой новый чат.

**Тебе прислали новый скилл (или обновили старый):** `cd ~/start-pack-skill && git pull && ./install.sh`. Всё.

**Ты сделал новый скилл и хочешь поделиться:** положи `.md` в `commands/` этого
репозитория, допиши секцию сюда в SKILLS.md, закоммить и запушь. Партнёр
получает его через `git pull && ./install.sh`.

## Процессные команды (основа TEAM-RULES)

### /brainstorming <задача>
Дизайн до кода. Изучает контекст проекта → задаёт уточняющие вопросы → предлагает
2–3 подхода с трейдоффами → фиксирует согласованный спек в `docs/specs/`.
Правило: никакого кода до утверждения спека. Для крупных и средних задач — вход
всегда отсюда (TEAM-RULES §1).

### /writing-plans <спек>
Из утверждённого спека делает детальный план реализации в `docs/plans/`: точные
пути файлов, готовый код шагов, критерий проверки каждого шага. Запрещены
заглушки и «доработаем позже».

### /executing-plans <план>
Исполняет план шаг за шагом: после каждого шага — верификация из плана, при
несовпадении — стоп и доклад, а не импровизация.

### /systematic-debugging <проблема>
Отладка через первопричину: воспроизведение → гипотезы → проверка по логам/коду →
только потом фикс. Запрещает «попробуем поменять и посмотреть».

### /tdd <фича>
Красный → зелёный → рефакторинг: сначала падающий тест, затем минимальный код,
затем чистка.

### /init
Сканирует репозиторий и создаёт/обновляет его `CLAUDE.md` (контекст проекта для
всех будущих сессий).

## Проверка и завершение (из obra/superpowers, MIT, адаптировано)

### /verification-before-completion [что проверяем]
Железное правило: никаких «готово/починил/работает» без свежего доказательства
в этом же ответе. Таблица «утверждение → чем доказывать» (тесты, смоук старта,
симптом бага, вёрстка глазами, прод — запросом/SQL, работа субагента — по
`git diff`). Нельзя проверить — так и сказать, что не проверено.

### /receiving-code-review [замечания]
Разбор замечаний ревью: прочитать все → пересказать → проверить по коду →
ответить → внедрять по одному с проверкой. Непонятно хоть одно — сначала
спросить. Внешним замечаниям не верим на слово, «сделай как положено» —
сначала grep, используется ли. Без «Вы абсолютно правы!» и благодарностей.

### /finishing-a-development-branch
Закрытие ветки: тесты + `/code-review` → базовая ветка → меню из трёх
вариантов (PR по умолчанию / оставить / локальный мерж) → уборка worktree.
В репо Vega с автодеплоем — только PR, мерж по явной команде. Удаление работы —
только по слову `discard`, `--force` и force-push — никогда сами.

## Вики (память проекта)

### /wiki-ingest <источник>
Сохраняет знания в `wiki/` проекта. Источник: пусто/`session` — текущая сессия
(авто-суммаризация), путь — файл (в т.ч. `.jsonl`-транскрипт другого чата),
http(s) — ссылка. Флаг `--global` пишет в `~/.claude/wiki/` вместо проектной.
Обновляет `index.cache.json` и `log.jsonl` — по ним работает поиск.

### /wiki-query <вопрос>
Отвечает по накопленной вики: ищет релевантные страницы по индексу, читает их и
собирает ответ со ссылками на страницы. Не выдумывает: чего нет в вики — так и
говорит.

## Передача контекста между чатами (handoff) и экономия токенов

Зачем: чат раздулся → каждый вопрос стоит как 5–18 вопросов в свежем чате (цена =
обращений на вопрос × контекст × цена модели), впереди автокомпакт с неконтролируемой
потерей деталей. Вместо этого — «слепок» + «записка сменщику». Цикл: в старом чате
`/handoff-ingest` (всегда ПОСЛЕДНЕЕ действие) → новый чат → `/handoff-query`.

Записки: по умолчанию один файл `docs/HANDOFF.md` на проект. Если в проекте есть папка
`docs/handoff/` — **по нитям**: одна параллельная нить (чат) — один файл
`docs/handoff/<slug>.md`, а `docs/HANDOFF.md` — оглавление со статусами. Нужно, когда
несколько чатов работают над одним репо и затирают общую записку.

Инструменты (ставит `install.sh` в `~/.claude/tools/`): `handoff/measure.py` — замер
сессии по её транскрипту (`stats`, `prep`, `query-prep`, `gauge`, `dialog`, `limits`);
`usage/limits.sh` — лимиты подписки как на экране `/usage` (ключ входа из связки ключей
macOS, ничего не сохраняет; адрес сервера недокументирован — при поломке даёт «нет данных»).

### /handoff-ingest
Хендофф-«слепок» — ≤7 обращений с полным контекстом вместо 13–15:
1. `measure.py prep` — один вызов: замер (контекст на вопрос, экономия ×N, лимиты), очищенный разговор, коммиты/PR сессии, заголовки вики → `~/.claude/handoff/<сессия>/`.
2. Сортировщик (агент, Sonnet) → таблица тем: 🟢 в проде/принято · 🟡 в работе · 🔴 отказались · ⚪ мусор, куда класть. Пользователь отвечает «ок» или правит строки.
3. Старая сессия ОДНИМ вызовом пишет слепок `dump.md`: записка + готовые тексты для страниц вики + TODO. Слепок локальный, в git не идёт (там могут быть секреты).
4. Раскладчик (агент, Sonnet): в отдельном worktree раскладывает вики, пишет записку и TODO, проверяет diff на секреты, PR → merge, ставит `done`.
5. Контролёр (агент, Sonnet) сверяет слепок, разговор и вики; пропуски дописывает раскладчик.
6. Чат помечается «🚫 …», финал: замер, лимиты, что сохранено, какую модель брать новой нити.
Упал раскладчик — слепок на диске, `/handoff-query` в новом чате доразложит.

### /handoff-query [приоритет 1|2|3] [нить]
1. `git pull --ff-only` + `measure.py query-prep`: записки и статусы, неразложенные слепки, стартовый контекст.
2. Неразложенный слепок своей нити → доразложить агентом (дёшево, контекст свежий).
3. Читает записку + TODO + git log; «ПРИНЯТА» — предупредит и предложит версию из истории.
4. `/wiki-query` по теме записки — вспомнить грабли до начала работы.
5. Гасит записку (ПРИНЯТА, стартовый контекст — факт), коммит; имя чата «<1️⃣|2️⃣|3️⃣> <имя>».
6. Доклад 6–9 строк: состояние, следующий шаг, вики, экономия, **рекомендуемая модель нити** (переключает пользователь: `/model`).

### /economy [цифры лимитов]
Режим экономии, запускается вручную у лимитов или чтобы дотянуть нить до паузы: один вызов
собирает лимиты и строку счётчика, затем три рычага командами для копирования —
`/effort medium|low` (меньше обращений на вопрос), `/model opus` для рутинных нитей
(Fable дороже вдвое и с отдельным недельным лимитом), агенты на Haiku/Sonnet; плюс
«окупится ли хендофф через N вопросов». Сессия сама меняет поведение до конца чата.

### Счётчик в шапке (личный хук, не в паке)
`measure.py gauge` в хуке UserPromptSubmit: при контексте ≥150 тыс. кладёт строку
«📏 контекст 312 тыс. · хендофф окупится через 2 вопр. · или /effort medium — ≈4 обращения
на вопрос вместо 7 · ⚠️ 82% окна — скоро автосжатие». Считает по последним 5 вопросам,
читает только хвост транскрипта (~0,08 с). Подключение — одна строка в `~/.claude/settings.json`.
